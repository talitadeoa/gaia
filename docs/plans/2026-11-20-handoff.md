### Armadilhas já descobertas (não repita)

1. **SSE: assine a fila ANTES de enviar os cabeçalhos.** O cliente desbloqueia
   no header e emite imediatamente; assinar depois perde o evento para sempre.
2. **Quem espera aprovação é o `RemoteUI`**, não o `Target`. O transporte
   resolve a UI primeiro (`resolve_permission`) e só depois avisa o alvo. Se
   invertermos, o turno trava até o timeout de 300s.
3. **`ui.permission` recebe `request_id`** (mudou em `turns.py`). Sem ele não há
   como esperar a decisão; o padrão é negar.
4. **O repo do mini tem `.git` próprio e antigo** (`aca6724`): `gmin deploy`
   exclui `.git`. `git log`/`git status` no mini não refletem o código real.
5. **Dois donos do Telegram = briefing duplicado** e 409. Sempre um só.
6. **`gmin deploy`/`gmin restart`** já escolhem a unidade ativa — não reinicie
   `gaia-telegram` se o `gaia-serve` estiver no comando.
7. **Não rode `gaia serve` apontando para `~/gaia/data`**: banco velho + workers
   proativos. Use `GAIA_DATA_DIR=/tmp/x GAIA_TELEGRAM_ENABLED=false`.
8. **`sudo` no mini**: `sudo -n` só funciona para `apt-get`; qualquer outro
   binário pede senha (que o agente não tem). Para escrever em `/etc` sem senha
   existe só o truque do hook do `apt-get` — não use sem necessidade.
